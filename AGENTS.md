**Purpose**
- Repo supplies a minimal **iOS‑malware analysis sandbox**: scripts to fetch a malicious IPA, unpack it, and search for network artefacts, plus the **C2 web‑panel source** that the attacker uses to configure the app at runtime.

**Directory layout**
- `grabipa.sh` / `geturl.sh` – entry‑point helpers (see below).
- `target0` … `target4` – each contains:
  - `target_malware.ipa` (or a similarly named IPA) – the compiled app.
  - `manifest.plist` – OTA‑install manifest; includes bundle ID (`com.dataapp.dataCollector`) and the download URL for the IPA (e.g. `https://mzi3ngewmjc2.baqew.com/...`).
  - `extracted_<app>.ipa/` – result of `geturl.sh`; full app bundle with frameworks, assets, and binaries.
  - `c2_*.js` – beautified Vue 3 / Element‑Plus source for the attacker’s control panel.
  - `C2_DASHBOARD_RE_REPORT*.md` – autogenerated markdown reports.

**Setup**
- Install required Unix tools: `bash`, `curl`, `unzip`, `strings`, `python3`.
- Make scripts executable: `chmod +x grabipa.sh geturl.sh`.

**grabipa.sh**
- Usage: `./grabipa.sh "itms-services://?action=download-manifest&url=..."`.
- Takes a single itms‑services URL, extracts the manifest URL, fetches the plist with an iPhone Safari UA, parses `bundle-identifier` and `software-package` URL, and downloads the IPA as `<bundle‑id>.ipa`.
- Exits on any error (`set -euo pipefail`).

**geturl.sh**
- Usage: `./geturl.sh <path_to_ipa>`.
- Verifies file existence, deletes any prior `extracted_<ipa>` dir, `unzip -q` the IPA, locates the first `.app` bundle in `Payload`.
- Scans executables, `.dylib` files, and any file marked executable with `strings` for:
  - IPv4 addresses (excluding localhost, 0.*, 255.*).
  - URLs not matching the built‑in whitelist.
- Whitelist (add more as needed): `apple.com`, `flutter.dev`, `w3.org`, `openssl.org`, `haxx.se`, `curl.se`, `gnu.org`, `pub.dev`.
- Prints suspicious IPs/URLs with the relative path inside the app bundle.
- Leaves unpacked files in `extracted_<ipa>` for manual inspection.

**Batch analysis tip**
```bash
# Scan all IPA files across targets
for ipa in target*/target_*.ipa target*/target_malware.ipa; do
  [ -f "$ipa" ] && ./geturl.sh "$ipa"
done
```
- Adjust the pattern if target directories use different naming schemes.

**C2 panel (c2_*.js)**
- Vue 3 + Element‑Plus UI bundled into single‑file JS; provides admin interface for the malicious client.
- Key API endpoints (used by the panel):
  - `GET  /manage/config/app-frontend` – returns current front‑end config (login/after‑login background image URL lists and `redirect_url`).
  - `POST /manage/config/app-frontend` – persists edited config.
  - `POST /manage/config/upload-image` – multipart/form‑data upload of a single image; response `{ data: { url } }` is pushed onto the appropriate list.
- State model (JSON): `{ login_bg_list: [], after_login_bg_list: [], redirect_url: "" }`.
- Legacy fallback: if the server returns `login_bg` / `after_login_bg` (single‑string fields) without the `*_list` arrays, the panel synthesises a one‑item list.\n**Important quirks**
- `geturl.sh` does **not** filter C2 server domains, so any embedded C2 URLs will appear as suspicious output – this is intentional for analysis.
- Running `grabipa.sh` on a manifest that points to a CDN (e.g., `baqew.com`) can be a red flag for malicious distribution.
- Unpacking an IPA overwrites any existing `extracted_<ipa>` directory; avoid if you need to keep previous results.
- The repo contains no test suite; all verification is manual via the scripts and by reading the JavaScript source.

**Typical investigation flow**
1. Obtain the manifest URL (from a phishing link or `targetX/manifest.plist`).
2. Run `./grabipa.sh "<itms‑services‑url>"` **or** use the already‑provided IPA (`targetX/target_malware.ipa`).
3. Run `./geturl.sh <ipa>` (or the batch loop) to unpack and list suspicious network artefacts.
4. Open the `c2_*.js` files to understand how the attacker can modify UI assets and the final redirect URL without rebuilding the IPA.
5. Optionally, inspect `C2_DASHBOARD_RE_REPORT*.md` for example outputs.

**Caveats**
- Scripts abort on missing commands or malformed input – double‑check arguments.
- Large IPAs require sufficient disk space; clean up old `extracted_*` dirs after analysis.
- Whitelist may need project‑specific extensions; edit the array in `geturl.sh` accordingly.
